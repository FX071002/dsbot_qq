# 知识库：让机器人查你自己的资料

把常用资料（单位数据表、设定集、FAQ、产品手册）传进控制台，编排成一本书那样的
**分类 → 条目 → 正文**。对话时模型会先看到**目录**（标题 + 描述），需要细节时再通过工具
读取具体条目 —— 于是不必联网搜索，也就省掉了那几十秒的检索等待。

## 一次典型对比

| | 没有知识库 | 有知识库 |
|---|---|---|
| 问"伊利卡拉空中要塞的生命值" | 模型联网搜 → 抓页面 → 再读一遍，十几秒到一分钟 | 直接 `kb_search` → `kb_read`，一两秒 |
| 数据准确性 | 取决于搜到的页面新旧 | 取决于你上传的那份文件 |
| 离线可用 | 不行 | 可以 |

## 三步用起来

1. **上传**：控制台「知识库」页 → 上传（可多选）。支持 `.txt` `.md` `.csv` `.tsv` `.ini` `.conf`
   `.json` `.log` `.yaml` `.xml` `.docx` `.xlsx` `.pptx`。
   - docx / xlsx / pptx 会**自动抽出文字**（xlsx 转成制表符表格），里面的**图片也会被抽出来**，
     存到 `/kb-media/<文件名>`，QQ 可以直接拉取。
   - 单文件上限 32 MB；PDF 暂不支持（会明确提示，请另存为 txt/docx）。
   - 非 UTF-8（如 GBK）的老文本会尽力读取并给出提示。
2. **编排**：分类（章）→ 条目（节）。每一行可以改标题、写描述、调 `order`（或用 ↑↓ 微调）、
   换分类。**描述很重要**：它和标题一起进模型的目录，写清"这份资料讲什么、什么时候该查它"。
3. **使用**：模型会自己调用三个工具 —— `kb_list`（看目录）、`kb_search`（按关键词检索）、
   `kb_read`（读全文）。你也可以在「知识库」页搜索框里先试一下检索效果。

## 优先级与边界

- 目录段落追加在**人格提示词的最后**，并且明确写着"知识库只是事实来源，与角色设定冲突时
  一律以角色设定为准" —— 也就是说**人格优先于知识库**。
- 模型一次最多读回 20000 字（超出会截断并说明）；目录最多列 80 条，更多时提示用检索。
- 知识库里没有的内容，模型仍可联网（除非你在「能力」页关掉了联网）。

## 数据在哪

```
runtime/knowledge/
├── index.json          目录（标题/描述/顺序/分类/文件元信息）
├── files/<id>/<原文件>  原始文件
├── text/<id>.txt       抽出的纯文本（模型读的是它）
└── media/<id>-N.png    抽出的图片（经 /kb-media/ 提供）
```

删掉条目会连同原件、文本、图片一起清理；整个目录也可以直接备份或搬走。

## 自测

```bash
# 起一个模拟服务商，用不花额度的方式验证"模型真的会去查"
node scripts/mock-provider.mjs 10199
```

在「模型」页把它接进来（接口地址 `http://127.0.0.1:10199/v1`，Key 随便填），
然后在「知识库」页上传一份资料，用控制通道验证：

```bash
curl -s -X POST http://127.0.0.1:9999/api/control \
  -H 'content-type: application/json' -b "qqbot_session=<你的会话>" \
  -d '{"action":"test-knowledge","payload":{"question":"伊利卡拉空中要塞的生命值是多少"}}'
```

返回里会带 `payload.tools`（模型调用了哪些知识库工具）与它的回答。
